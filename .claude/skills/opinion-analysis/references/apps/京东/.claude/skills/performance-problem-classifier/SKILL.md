# 京东应用的性能舆情问题分类器

基于已构建的树状态分类体系，对用户反馈的性能舆情问题中的描述信息进行逐层分类，输出 JSON 格式的分类结果。

## 调用时机

- 需要对性能舆情的数据进行层级分类/归类/分类打标时
- 主流程中需要进行数据分类分析的阶段

## 重要规则（必须遵守）

**分类过程规范：**
- **逐层分类，禁止跳层**：必须从根节点开始，逐层向下分类，禁止直接判断深层类别。每一层都必须从候选列表中选择，不可自行臆断。
- **仅限候选范围**：每一层分类时，只能从相应的子类别中选择。
- **提前终止条件**：当满足以下任一条件时，停止继续向下分类：
  1. 当前节点无子节点（叶子节点）；
  2. 描述信息模糊，无法区分当前层的候选类别（需明确说明判断依据）；
- **禁止猜测**：如果描述信息不足以判断类别，宁可提前停止也不猜测。分类的结果必须从指定的类别体系中获取，禁止添加类别。
- **禁止批量处理**：数据文件可能包含大量记录，必须逐条处理，不可一次性将所有描述信息送入分类。
- **禁止忽略子类详情**：如果识别到问题属于某一类时，必须阅读其子类，必须确认下辖类别详情，不可忽略子类详情而停止。
- **如何处理非性能问题**：如果从问题的描述中确认它不属于性能问题，则直接停止，输出**未知问题**。
- **仅处理京东端问题**：如果从问题的描述中确认它不是京东应用（如其它电商或导购类应用），则直接停止，输出**未知问题**。
- **如何处理多类问题**：如果从问题的描述中发现存在多个问题，你只需要关注其中的性能问题，忽略其它非性能问题，如果仍然有多个性能问题，你可以选择最主要的一个问题进行分类，忽略其它非主要问题。

## 京东性能舆情问题分类体系介绍

本分类体系专为"京东"应用的性能问题设计。

### 1、分类体系设计原则

#### 1.1 设计背景

本分类体系针对"京东"应用的性能问题进行分类，旨在通过统一的分类标准，快速定位问题类型，为后续优化提供依据。

#### 1.2 四大类性能问题

从现象维度，性能问题的核心表现就是卡、慢，因此性能问题都属于**“卡顿”**这一个大类。进一步，根据具体的表现，将京东应用的性能问题分为以下4大类：

| 大类 | 核心特征 | 含义 |
|------|------|------|
| **动效卡顿** | 动态过程不流畅 | 应用页面处于动态过程中（如滑动、视频播放、动画特效等）存在不流畅现象 |
| **响应慢/加载慢** | 操作响应延迟或内容加载慢 | 操作后响应不及时或页面内容加载慢，甚至完全无反应 |
| **启动慢** | 应用拉起过程慢 | 拉起应用的过程很慢，包括冷启动和热启动 |
| **其他性能问题** | 明确不属于上述三类 | 明确上述三类无法覆盖的性能问题 |

- **重要：**如果从问题的描述过于模糊，无法从中确认它是“动效卡顿”、“响应慢/加载慢”，“启动慢”时，不能将其归属于“其他性能问题”，而是应该将它归属于**“卡顿”**这一个所有大类的父类当中。

#### 1.3 动效卡顿类性能问题

**动态过程的典型场景**：
- 滑动页面（首页推荐流、商品详情页、搜索结果列表、购物车、订单列表等上下滑动）
- 视频/直播播放（商品主图视频、直播间）
- 页面转场（页面切换）
- 动画特效播放（加购弹窗、优惠券/促销动画）

**包含子类**：

| 类别 | 说明 | 下辖类别详情 |
|------|------|------|
| **滑动卡顿** | 各页面滑动过程中存在卡顿 | `references/动效卡顿-滑动卡顿.md` |
| **视频播放卡顿** | 商品主图视频或直播间视频播放卡顿 | `references/动效卡顿-视频播放卡顿.md` |
| **页面转场卡顿** | 页面切换时明显不流畅 | 无 |
| **动画卡顿** | 应用动画特效卡顿（加购弹窗、优惠券/促销动画） | `references/动效卡顿-动画卡顿.md` |

#### 1.4 响应慢/加载慢性能问题

**操作响应的典型场景**：
- 点击按钮后响应迟钝（搜索/立即购买/加入购物车/结算/支付确认）
- 手势操作（侧滑返回、商品图片缩放）后页面不跟手
- 页面内容加载需要较长时间
- 操作后页面完全无反应

**重要说明**：
- **网络卡顿也属于响应慢/加载慢**，因为网络卡顿的表现类似于响应慢、加载慢
- 只有用户**明确提到**网络原因时，才归入"网络卡顿"子类
- 用户未明确提到网络原因时，根据实际现象归类到"按钮点击响应慢"、"手势操作响应慢"、"页面加载慢"、"操作无响应"

**包含子类**：

| 类别 | 说明 | 下辖类别详情 |
|---------|------|------|
| **按钮点击响应慢** | 点击按钮时响应不及时，有明显迟钝 | `references/响应慢加载慢-按钮点击响应慢.md` |
| **手势操作响应慢** | 手势操作（侧滑、图片缩放）时响应迟钝、不跟手 | `references/响应慢加载慢-手势操作响应慢.md` |
| **页面加载慢** | 页面内容加载很慢 | `references/响应慢加载慢-页面加载慢.md` |
| **操作无响应** | 操作后页面没有任何反应 | `references/响应慢加载慢-操作无响应.md` |
| **网络卡顿** | 用户反馈明确包含网络方面的原因 | `references/响应慢加载慢-网络卡顿.md` |

#### 1.5 启动慢性能问题

**启动场景**：
- **冷启动**：应用从完全关闭状态启动
- **热启动**：应用从后台唤醒到前台

**包含子类**：冷启动慢、热启动慢

| 类别 | 说明 | 下辖类别详情 |
|---------|------|------|
| **冷启动慢** | 应用冷启动慢 | `references/启动慢.md` |
| **热启动慢** | 应用热启动慢 | `references/启动慢.md` |

#### 1.6 其他性能问题

**定义**：不属于"动效卡顿"、"响应慢/加载慢"、"启动慢"三大类的性能问题。

**重要说明**：
- 网络卡顿**不是**其他性能问题，网络卡顿属于"响应慢/加载慢"
- 所有无法明确归类到前三类的性能问题，都归入"其他性能问题"

#### 1.7 分类决策核心原则

**最重要原则：根据用户描述的实际现象进行分类，不要过度联想或脑补。**

分类时应：
1. 仔细阅读用户描述，提取关键特征
2. 将关键特征与各大类别的定义逐一比对
3. 选择匹配度最高的类别
4. 如果无法确定属于哪个子类，**停止逐级分类**，归入当前父类

## 分类步骤

**最重要原则：根据用户描述的实际现象逐层进行分类判断，不要过度联想或脑补。**

1. 仔细阅读用户描述，提取关键特征
2. 将关键特征与各大类别的定义逐一比对
3. 选择匹配度最高的大类别
4. 仔细阅读该类别的子类详解；
5. **必须**: 仔细阅读子类别详情，确认所属的子类别，以此往复
6. 如果无法确定属于哪个子类，**停止逐级分类**，归入当前父类

---

## 输出格式

**严格按照json格式进行输出，结果中既要包含分类结果，也要包含分类的推理过程。**
```JSON
{
    "result": "XXX",
    "reason": "XXX"
}
```

分类结果 result 为各级类别用 `-` 连接的完整路径，如：
`响应慢/加载慢-页面加载慢-商品详情页加载慢`

## 京东性能舆情问题分类示例：

### 示例1：
- **用户描述**：京东商品详情页往下滑的时候一卡一卡的，图片加载也慢
- **分析过程**：用户描述在商品详情页向下滑动时卡顿，从动效卡顿、响应慢/加载慢、启动慢、其他这四个大类中确定该问题属于“动效卡顿”，下滑动作为滑动过程，二级分类为“滑动卡顿”，明确指向商品详情页，三级分类为“商品详情页滑动卡顿”。（图片加载慢属另一问题，按多类问题取最主要的一个）
- **分类结果**：动效卡顿-滑动卡顿-商品详情页滑动卡顿

### 示例2：
- **用户描述**：京东app点结算没反应，要多点几次
- **分析过程**：用户描述点结算按钮后无反应，属于“响应慢/加载慢”大类，操作后无反应对应“操作无响应”，结算位于购物车结算流程，对应“下单无响应”。
- **分类结果**：响应慢/加载慢-操作无响应-下单无响应

### 示例3：
- **用户描述**：京东打开很慢，点进去要等好久才出内容
- **分析过程**：用户描述应用启动慢，从四大类中确定属于“启动慢”，未明确是冷/热启动且描述偏冷启动场景，按规则不确定子类时停止于父类。
- **分类结果**：启动慢
