# 抖音舆情分析

基于已经构建的树的状态分类体系，对用户反馈的性能舆情问题中的描述进行逐层分类，输出JSON格式分类结果

# 调用时机

- 需要对舆情性能的数据进行层级分类/归类/分类打标时
- 主流程中需要进行数据分类分析阶段

## 重要规则（必须遵守）
**分类过程规范：**
- **逐层分类，禁止跳层**：必须从根结点开始，逐层向下分类，禁止直接判断深层类别。每一层都必须从候选列表中选择，不可自行臆断。
- **仅限候选范围**：每一层分类时，只能从相应的子类别中选择。
- **提前终止条件**：当满足以下任意一个条件时，停止继续向下分类：
  1. 当前节点无子节点（叶子节点）；
  2. 描述信息模糊，无法区分当前层的候选类别（需明确说明判断依据）；
- **禁止猜测**：如果描述信息不足以判断类别，宁可提前停止也不猜测。分类的结果必须从指定的类别体系中获取，禁止添加类别。
- **如何处理非性能问题**： 如果确认不是性能问题，输出**未知问题**。
- **仅处理鸿蒙端问题**： 如果非鸿蒙抖音问题，如“卓易通”（安卓抖音），直接停止，输出**未知问题**。
- **如何处理多类问题**：如果有多个问题，只关注性能问题，如果仍有多个性能问题，选择最主要的问题进行分析，忽略其他的非主要问题。

## 抖音舆情分类体系介绍

本分类体系专门为“抖音”鸿蒙应用的性能问题设计。

### 1、分类体系设计原则

#### 1.1 设计背景

本分类体系针对“抖音”鸿蒙应用的性能问题进行分类，旨在通过统一的分类标准，快速定位问题类型，为后续优化提供依据。

#### 1.2 四大性能问题

从现象维度，将抖音鸿蒙应用的性能问题分为以下4大类：

| 大类 | 核心特征 | 含义 |
|------|---------|------|
| **动销卡顿** | 动态过程不流畅 | 应用页面处于动态过程中（如滑动、视频播放、动画特效等）存在不流畅现象 |
| **响应慢/加载慢** | 操作响应延迟或内容加载慢 | 操作后响应不及时或页面内容加载慢，设置完全无反应 |
| **启动慢** | 应用拉起过程慢 | 拉起应用的过程很慢 |
| **其他性能问题** | 不属于上述三类 | 上述三类无法覆盖的性能问题 |

- **重要：**如果问题的描述过于模糊，无法从中确定它是“动效卡顿”、“响应慢/加载慢”，“启动慢”时，不能将其归属于“其他性能问题”，而是应该将它归属于**“卡顿”**这一个所有大类的父类当中。

#### 1.3 动效卡顿类性能问题

**动态过程的典型场景**
- 视频滑动（上下滑动、左右滑动）
- 视频播放
- 视频/语音通话
- 页面转场（页面切换）
- 观看直播
- 动画特效播放
- 拍摄/剪辑过程
- 小程序运行

**包含子类**：

| 类别 | 说明 | 下辖类别详情 |
|------|-----|-------------|
| **滑动过程** | 应用各页面滑动过程中存在卡顿 | `动效卡顿-滑动卡顿.md` |
| **视频播放卡顿** | 首帧出不来（黑屏）或停在首帧迟迟播放不了 | `动效卡顿-视频播放卡顿.md` |
| **视频/语音通话卡顿** | 使用视频/语音通话功能时发生卡顿 | 无 |
| **页面转场卡顿** | 页面切换明显不流畅 | 无 |
| **直播卡顿** | 进入直播间、观看直播、切换直播间、直播互动、直播购物等过程卡顿（含直播购物卡顿） | `动效卡顿-直播卡顿.md` |
| **动画卡顿** | 用用动画特效卡顿（如按钮动画特效），区别于视频播放卡顿 | `动效卡顿-动画卡顿.md` |
| **拍摄/剪辑卡顿** | 拍摄、剪辑及视频发布过程卡顿 | `动效卡顿-拍摄剪辑卡顿.md` |
| **小程序卡顿** | 抖音小程序相关卡顿（含抖音游戏卡顿） | 无 |

**子类详解**： `动效卡顿子类详解.md`

#### 1.4 响应慢/加载慢性能问题

**操作响的典型场景**
- 点击后按钮响应慢
- 手势操作（侧滑、上下滑）后页面不跟手
- 页面内容加载需要较长时间
- 操作后页面完全无反应

**重要说明**
- **网络卡顿也属于响应慢/加载慢**，因为网络卡顿的表现类似于响应慢、加载慢
- 只有用户**明确提到**网络原因时，才归入“网络卡顿”子类
- 用户为明确提到网络原因呢时，根据现象归类到“按钮响应慢”、“手势操作响应慢”、“页面加载慢”、“操作无响应”

**包含子类**：

| 类别 | 说明 | 下辖类别详情 |
|------|-----|-------------|
| **按钮点击响应慢** | 在点击按钮时，响应不及时，有明显的迟钝 | `响应慢加载慢-按钮点击响应慢.md` |
| **手势操作响应慢** | 在进行手势操作（如侧滑、上下滑）时，有明显的迟钝，页面状态不跟手 | `响应慢加载慢-手势操作响应慢.md` |
| **页面加载慢** | 页面的内容加载很慢，需要很长时间才能加载出来 | `相应慢加载慢-页面加载慢.md` |
| **操作无响应** | 操作后页面没有任何反应，包含了所有页面的无响应 | `响应慢加载慢-操作无响应.md` |
| **网络卡顿** | 由于网络原因导致了卡顿，这里面强调的是用户反馈的信息明确包含了网络方面的问题 | `响应慢加载慢-网络卡顿.md` |

**子类详解**： `响应慢加载慢子类详解.md`

#### 1.5 启动慢性能问题

**启动场景**：
- **冷启动**： 应用从完全关闭状态启动
- **热启动**： 应用从后台唤醒到前台

**包含子类**： 冷启动慢、热启动慢

| 类别 | 说明 | 下辖类别详情 |
| **冷启动慢** | 应用冷启动慢 | `启动慢.md` |
| **热启动慢** | 应用热启动慢 | `启动慢.md` |

**子类详解**： `启动慢子类详解.md`

#### 1.6 其他性能问题

**定义**： 不属于“动效卡顿”、“响应慢/加载慢”、“启动慢”三大类的性能问题。

**重要说明**
- 网络卡顿**不是**其它性能问题，网络问题属于“响应慢/加载慢” 
- 所有无法明确归类到前三类的性能问题，都归入“其他性能问题”

#### 1.7 分类决策的核心原则

**最重要原则：根据用户描述的实际现象进行分类，不要过度联想或脑补。**

分类时应：
1. 仔细阅读用户描述，提取关键特征
2. 将关键特征与各类别的定义逐一对比
3. 选择匹配度最高的类别
4. 如果无法确定属于哪个子类，**停止逐级分类**，归入分类当中


### 2、关键区分点汇总

#### 2.1 动效卡顿 vs 响应慢/加载慢

| 特征 | 动效卡顿 | 响应慢/加载慢 |
|------|---------|--------------|
| 页面状态 | 动态过程（滑动中、播放中） | 静态或操作后触发 |
| 典型场景 | 滑动过程、视频播放卡顿 | 按钮点击慢、页面加载慢 |
| 核心区别 | 页面本身在动，懂的时候不流畅 | 操作后反应慢/内容加载慢 |

#### 2.2 直播购物卡顿 vs 直播购物加载慢

| 类别 | 强调点 | 示例 |
|------|-------|------|
| 动效卡顿-直播卡顿-直播购物卡顿 | 页面**弹出**的动效卡顿 | 点击购物车，弹出的动画卡顿 |
| 响应慢/加载慢-直播购物加载慢 | 页面弹出后**内容加载**慢 | 购物车弹出来了，但是商品列表加载很慢 |

#### 2.3 动画卡顿 vs 视频播放卡顿

| 类别 | 强调点 | 示例 |
|------|-------|------|
| 动画卡顿 | **动画特效**本身的卡顿 | 点击按钮的动画特效、页面过渡动画卡顿 |
| 视频播放卡顿 | **视频播放**过程中的卡顿 | 视频播放时画面卡顿 |

#### 2.4 视频/语音通话卡顿 vs 页面转场卡顿

| 类别 | 强调点 | 示例 |
|------|-------|------|
| 视频/语音通话卡顿 | **通话功能**的卡顿 | 视频通话时画面卡顿 |
| 页面转场卡顿 | **页面切换**的卡顿 | 打开新页面时动画卡顿 |

#### 2.5 网络卡顿判定规则

| 条件 | 归类 |
|-----|------|
| 用户**明确提到**网络原因 | 网络卡顿 |
| 用户**未明确提到**网络原因 | 根据实际现象归类（按钮点击响应慢/手势操作响应慢/页面加载慢/操作无响应） |

## 分类步骤

**最重要原则：根据用户描述的实际现象逐层进行分类，不要过度联想或脑补。**

1. 仔细阅读用户描述，提取关键特征
2. 将关键特征与各类别的定义逐一对比
3. 选择匹配度最高的类别
4. 再进一步仔细阅读该类别的子类详解，以及子类别详情，确认所属的子类别，以此往复
5. 如果无法确定属于哪个子类，**停止逐级分类**，归入分类当中

## 终止条件

### 1 必须终止的情况

1. **描述信息模糊**：无法区分当前层级的候选类别
2. **无匹配类别**：不属于任何候选类别
3. **已是叶子节点**：当前类别无子节点
4. **非性能问题**：识别到用户描述的信息不属于性能问题
5. **非鸿蒙问题**：识别到用户描述的信息不属于抖音鸿蒙段应用

### 2 提前终止操作

当需要提前终止时：
1. 在 reason 中说明原因
2. 停止向下分类

### 3 终止示例

**场景**： 用户反馈“页面有点卡”

**分析**：
- 第一层：属于“动效卡顿”或“响应慢/加载慢”
- 问题现象模糊，无法确定是动态过程卡顿还是响应慢
- 决策：提前终止，归入“模糊”

## 抖音舆情性能分类示例：

### 示例1：

**用户描述**：抖音带耳机的时候，偶尔出现是因延迟，音画不同步，出现卡顿
**分析过程**：用户描述声音延迟且卡顿，说明是视频播放过程中出现了延迟，从动效卡顿、响应慢/加载慢、启动慢、其它这四个大类中确定该问题属于“动效卡顿”，而声音延迟和音画不同步说明用户在看视频，二级分类为“视频播放卡顿”，音画不同步的描述对应三级分类“音画不同步”，因此最终的分类结果为动效卡顿-视频播放卡顿-音画不同步。
**分类结果**：动效卡顿-视频播放卡顿-音画不同步

### 示例2：

**用户描述**：抖音app检查验货，页面反应迟钝，请确认是否正常
**分析过程**：从用户描述“页面迟钝”推测出一级分类为“响应慢/加载慢”，没有更多描述可以推测出该一级分类下的二级分类，因此过程终止。
**分类结果**：响应慢/加载慢

### 示例3：

**用户描述**：在抖音应用中，触屏划视频反馈不及时，甚至没有反应，需要滑动很多次或很用力划屏幕，才有缓慢反应
**分析过程**：根据用户的描述信息“触屏划视频反馈不及时”，从动效卡顿、响应慢/加载慢、启动慢、其他这四个大类中可以明确地确定该问题属于“响应慢/加载慢”问题，进一步地，用户说“划视频”，它是一个手势动作，上下滑动，因此在下辖的各个子类别中对应了“手势操作响应慢”类别，进一步地，由于是视频过程中的手势，因此确认子类别为“视频手势相应慢”，更进一步的，由描述“触屏划视频”可以确认是“上下滑动切换视频不跟手”类别。因此最终的分类结果为响应慢/加载慢-手势操作响应慢-视频手势响应慢-上下滑动切换视频不跟手
**分类结果**：响应慢/加载慢-手势操作响应慢-视频手势响应慢-上下滑动切换视频不跟手
